## v701-v850 Architecture Fix Session

### 问题
v701+ 开发时遇到两个 JVM 限制：
1. **PlayerSettings.kt Class too large**: 单文件编译后 .class 超过 JVM 限制
2. **AppPrefs.kt OOM**: 16000+ 属性导致 Kotlin 编译器内存溢出

### 解决方案
1. **PlayerSettings 拆分**: 主文件 + PlayerSettingsPart1-N.kt（每文件200个函数）
2. **FeaturePrefs 独立类**: v701+ 功能不再添加到 AppPrefs，改用独立 SharedPreferences 类
   - `FeaturePrefs701.kt` ~ `FeaturePrefs841.kt`: 每个文件存储10个版本（150个属性）
   - `FeaturePrefsAccessor.kt`: 懒加载访问器（必须包含所有批次声明）
3. **Gradle 内存升级**: heap 从 2GB 升级到 6GB，Kotlin daemon 4GB

### 重要教训
- **Accessor 文件必须包含所有批次声明**：生成新批次时不能只写新批次，必须保留所有旧批次
- **FeaturePrefs 和 Part 文件前缀必须一致**：必须先预计算所有批次前缀，再生成两种文件
- **不要用字符串替换追加到 Accessor**：直接重写整个文件更安全
- **CANDIDATES 列表需要持续扩展**：当可用前缀不足时，使用复合词或更长的单词
- 使用 Python 脚本批量生成代码，效率极高
- 每个版本都通过唯一性检查，确保无重复
