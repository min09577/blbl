# 2026-06-08 Daily Log

## v131-v150 Feature Development Session

### Key Learnings
1. **Placeholder-based code generation broke**: The `PLACEHOLDER_FUNCTION` / `PLACEHOLDER_SETTING` markers in PlayerSettings.kt were consumed by v121-v130 generation. Switched to **line-based insertion** approach.
2. **Property reference naming**: AppPrefs properties use version prefix (e.g., `v131audioChorusDepth`), but generation script initially wrote `BiliClient.prefs.audioChorusDepth` (wrong). Must use `BiliClient.prefs.v{ver}{name_lower}`.
3. **SharedPreferences variable name**: Existing code uses `prefs` not `mSharedPreferences`. Generation script must output `prefs`.
4. **Line-based insertion for AppPrefs.kt structure**:
   - Properties (`var`) go BEFORE `companion object` (line ~14651+)
   - Keys (`const val`) go BEFORE the closing `}` of `companion object`
   - Closing brace found by counting ALL `{` and `}` characters (not just stripped lines)
5. **String replacement pitfall**: Simple `str.replace()` doesn't respect boundaries. `danmakuFontBgFillShadowType` also matches `danmakuFontBgFillShadowType133`. Always use version-prefixed names in generated code.
6. **CI build tag management**: Tags must be deleted from remote before recreating: `git push origin :refs/tags/vXXX && git tag -d vXXX && git tag vXXX && git push origin vXXX`
